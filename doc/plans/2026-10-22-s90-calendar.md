# S90 Calendar production invocation

Date: 2026-10-22

## Goal

Make Calendar provider operations go through the existing Tool Gateway while
preserving the acting board user or authenticated agent run. Anonymous booking
uses a separately granted, narrowly scoped authority stored on the exact
booking type. A public slug or request body never carries a grant.

## Implemented in this source pass

- Calendar connector calls carry a discriminated, server-derived principal:
  board session, authenticated agent run, or public booking host.
- The authorized invoker has no startup work. It enforces a 30-second provider
  budget, caps arguments at 16 KiB, binds every call to its company, booking
  type, connection, event and host, and uses stable write idempotency keys.
- Agent calls mint a short-lived Tool Gateway session only from the active run
  attached to the authenticated request, then use the existing list/call path.
- Board and public host calls use a Tool Gateway method dedicated to Calendar.
  It admits only Google Calendar's four reviewed methods, reruns current tool
  policy and rate limits, resolves credentials/grants at execution, and records
  an invocation and redacted audit trail. Delegated calls are recorded as a
  service principal tied to the booking type and delegating administrator, not
  as a fabricated agent run or gateway session.
- Public execution defaults off. Enabling it requires a board user with
  users:manage_permissions, a configured host and Calendar connection, and
  saves the delegating user and timestamp. The delegator's permission, host,
  type, connection, active grants and tool policy are rechecked on every call.
- The Schedule form exposes connection, host and the explicit delegation
  checkbox. Its type list reports delegation state and offers revision-checked
  revoke; revocation is audited.
- Reschedule and cancel use the event's original connection and booking type;
  mismatched, revoked or archived context fails closed. Unknown provider
  outcomes are marked uncertain and cannot be blindly retried.

## Integration still owned by root

server/src/app.ts must construct one

registerPublicBookingRoutes, and the external-action retry service. No connector call should happen at service
construction or server startup. Root owns route/app registration, shared schema
exports and the consolidated migration.

The matching SQL fragment is in

## Policy boundary

The External Action gate still decides whether an agent action is draft,
approval-required or direct. The Tool Gateway policy is checked again for every
provider method. If the tool policy requests its own approval, provider
execution is denied and the booking remains blocked/unconfirmed. Calendar
delegation has no durable approval dispatcher, so any provisional action request
is cancelled and the invocation terminally denied; no approval is presented as
pending and no external-action approval bypasses Tool Gateway policy.

Public agent hosts are beneficiaries of a booking-type delegation only. They
do not acquire a generic agent identity or a heartbeat run. If the provider
grant, host membership, delegator permission or policy is unavailable, the
call fails closed.

## Verification constraints

No tests, typecheck, build, check scripts, server, migration, install, or
provider calls were run. The changes are source-level implementation only.

## Addendum de wiring y limites de ejecucion (2026-10-22)

La raiz monto una sola instancia de `googleCalendarService` con `createAuthorizedCalendarInvoker` y la inyecto en `calendarRoutes`, la superficie publica `/p` y `externalActionRecoveryRoutes`. El invoker no resuelve credenciales ni hace red al construir el servidor; la conexion, el grant y la policy se vuelven a evaluar en cada invocacion. Los contratos de calendario usados por estas rutas son internos de servidor; el listado de tipos y las entradas UI viajan por el API de la aplicacion, por lo que no se agrega un contrato duplicado en `packages/shared`.

La ruta de reserva publica solo puede ejecutar cuando el booking type tiene `publicExecutionEnabled` y delegacion vigente de una persona con `users:manage_permissions`; la revocacion o perdida de permiso bloquea nuevas llamadas. La identidad de servicio usa `delegated_service` ligada al booking type. La ruta autenticada board usa el usuario operador y sus grants propios; no hereda el agente o usuario host del tipo. En la decision de Tool Gateway se pasa `session.agentId`, que es nulo para board y solo contiene el agente host en la delegacion publica autorizada.

Tool Gateway vuelve a comprobar que la conexion de la empresa exista, este activa y habilitada, y que su `sourceTemplateKey` sea `google-calendar` o su URL use el host canonico `calendarmcp.googleapis.com`; no confia en el nombre de marca de la aplicacion. La herramienta debe venir de la conexion exacta y su `upstreamToolName` debe ser uno de los cuatro metodos permitidos; el alias local del gateway no sustituye al nombre upstream. Una repeticion de una mutacion sin recibo reproducible termina en resultado incierto y requiere inspeccion; no se reenvia a ciegas. Si la policy de herramientas pide su propia aprobacion, la invocacion se deniega y cualquier solicitud provisional se cancela, porque esta delegacion no tiene un dispatcher durable de aprobacion.

El servicio de reintento de acciones externas recibe la misma instancia de calendario, pero los resultados inciertos siguen bloqueados hasta reconciliar el evento o recibo del proveedor. No se ejecutaron llamadas reales al proveedor.
