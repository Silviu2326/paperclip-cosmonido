**Date:** 2026-10-22

## Scope

Spanish (es), English (en) and Portuguese (pt-BR, pt-PT) dictionaries for the reachable S4 productization panels and pages, plus a language selector. Other locales keep every existing message and receive the English text for the new keys.

## Merge rule

- `mergeMissingMessages` is pure and additive. Existing messages always win; objects merge recursively, so `nav`, `common` and `agent` keep their existing entries. For example, `nav.productization` stays "Business setup" in en.json.
- `es` gets the Spanish dictionary, `en` the English, `pt-BR` and `pt-PT` the Portuguese. Any other locale gets the English text.
- Interpolation placeholders are the same in all three languages. Checked by search: the set of `{{…}}` names matches per key.
- No plural forms are used.

## Language selection and persistence

There is no server-side locale preference, and this change does not add one (that needs a migration, an API field and a validator change). The selector follows the browser-local pattern of `ThemeContext`:

- Storage key `paperclip.locale.<userId>`, value one of `es`, `en`, `pt-BR`, `pt-PT`.
- Changing the select calls `i18n.changeLanguage` (existing instance) and then persists under the signed-in user's id.
- No session: the change applies to the page only, and the page says so. Storage errors show an alert. They are not hidden.
- Keyed by user id, not company, so company switching does not change the language. Account switching re-applies the new user's saved value, or the default (`es`), so one user's language never leaks to another.

## Wiring the parent must do

1. **Route:** in `ui/src/App.tsx`, add `<Route path="language-settings" element={<LanguageSettings />} />` inside the company shell, with `import { LanguageSettings } from "./pages/LanguageSettings";`.
2. **Apply the saved language:** mount `useLanguagePreferenceSync(session?.user.id)` once inside the authenticated shell, where the session query is available. Without it, a saved language is only applied when the page itself mounts.
3. **Sidebar:** add `<SidebarNavItem to="/language-settings" label={t("nav.languageSettings")} icon={…} />`. The key exists in all three dictionaries.

## Remaining translation gaps (honest)

**Hard-coded text in feature files (not `t()`, so no dictionary can localize it):**
- `catalog/PortableCatalogPanel.tsx`: `STATUS_LABELS`; the three `parsePackageJson` messages; `toLocaleString()` date formatting.
- `catalog/PackageInstallPanel.tsx`: `statusLabel()`; the generated default instruction headings `## Criterios de entrega`.
- `hiring/ProfileHirePanel.tsx`: `pendingReasonCopy()`; `responseStatusCopy()`.
- `onboarding/ProductOnboardingPanel.tsx`: `useJourneyAction` messages ("La respuesta corresponde a otro recorrido…", "No se pudo guardar. Revisa la conexión…"); `formatDuration` units (`d`, `h`, `min`).
- `pages/Productization.tsx`: "Abrir constructor de negocio"; several thrown error messages.

Those components are not in this worker's ownership. Converting them to `t()` is the next step, and the keys to use are already in the dictionary where a matching key exists.

**Other limits:**
- **pt-PT** receives the same Portuguese text as pt-BR (Brazilian wording). Its existing `pt-PT.json` messages are preserved.
- **Other locales** (about 37) show English for the new S4 keys. This is a fallback, not a translation.
- **Portal statuses** (deliverable, meeting, conversation and commitment `status`, and `actorKind`) are plain strings in the shared types, so they are shown as received.
- **Built-in media notes:** only the two known shared notes are mapped. Other shared English text stays as is. `metrics.basis` is server text and stays as is.
- **Metric labels:** server metric keys outside the ten in `productMetrics.labels` display their raw key.
- **Server error messages** are shown verbatim. They are not localized.
- **Business builder, accounts, security and notification pages:** not in the S4 key inventory, and their owners were still working. `ProductBilling` keys were read and added to the dictionary.

**Behavior limits:**
- Before the session resolves, the default (`es`) is shown, even for a user who saved another language. The saved language then applies.
- The preference is per browser, not per account across devices. A durable cross-device preference needs a server field, which is a separate migration task.
- `document.documentElement.lang` is not updated.
