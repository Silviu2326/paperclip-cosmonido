# S95 UI i18n coverage

This increment extends the additive S90/S95 message layer in `ui/src/i18n/s90-messages.ts`. English defines the key shape; Spanish and Portuguese provide parallel additions. `locales.ts` merges missing leaves into existing locale trees, and the established per-user language preference remains unchanged. Other shipped locales receive English fallback for these additions.

## Coverage wired in this increment

- Pricing, public signup and billing intent/verification/trial/checkout states: EN/ES/PT dictionaries; the pages use the existing productization messages and newly added signup/billing leaves.
- Business home and web-chat dispatcher settings: EN/ES/PT copy, including the recorded-check wording that makes no freshness claim.
- Security settings: EN/ES/PT for the account/TOTP flows, session and retention/account-deletion panels, previews, pending deletion state, and blocker presentation. Known domain state labels remain distinct.
- Commercial accounts: creation, linking, membership and recorded usage labels now use EN/ES/PT messages. Server error detail remains visible alongside a translated summary where provided.
- Public catalog: EN/ES/PT coverage for publication requests, moderation, imports, ratings, and request-state receipts. A pending request is presented as pending; unknown status is not presented as success.
- Agency workspace, notification action, Config Copilot and CRM sync: EN/ES/PT dictionary coverage is added and wired for the principal interactive labels and state summaries. CRM keeps raw server reasons and uncertain-operation states visible. Config Copilot maps known model/authorization, budget, version-conflict and uncertain-outcome failures to distinct translated explanations; unexpected errors use the generic message.
- Customer portal pages use the existing productization message layer for static copy. Added EN/ES/PT leaves for the newly shipped portal file grants, upload limits, pending/confirmed upload receipts, server-side file visibility and feedback wording. Existing CSV contracts and idempotent upload requests are untouched; data values and server errors remain visible.

## Remaining limits

This is not complete localization of every sentence in every S95 surface. Some secondary explanatory copy and API-supplied domain strings in Agency Workspace, CRM sync, Security Settings, account administration and customer portal status/data values remain Spanish or server-provided. Locale coverage outside EN/ES/PT uses English fallback. This change does not alter API error contracts, language preference behavior, or operation semantics.

The authorized UI typecheck (`pnpm.cmd --filter ui exec tsc -b`) was attempted. It reports no errors in `PublicCustomerPortal.tsx`, `CustomerPortalSettings.tsx`, or `productization-messages.ts`; the overall UI typecheck still fails in `locales.ts`, `LanguageSettings.tsx`, `BusinessBuilder.tsx`, `PublicCatalog.tsx`, `SecuritySettings.tsx`, and Storybook feature-map imports/types. No tests, browser checks, build, generators, or provider actions were run.
