# S4 productization: Media templates and brand presets

Date: 2026-10-22

## What this implements

- Five reusable starters: social clip, product demo, testimonial, tutorial and short advert. Their requirements and operation recipes are versioned as shared contract data.
- Company presets append immutable versions under a stable key. The API validates operation payloads with Media Studio's existing validator and validates referenced media assets against the same company.
- The board screen selects a company video file, creates a normal Media Studio project, submits the template's supported operations through the existing Media Studio client, and queues the existing render job. Transcription is a separate, clearly labeled action that goes through the existing provider credential, budget and queue checks.
- Existing output assets are opened through the existing company-authorized asset content route. No new processing or storage endpoint was introduced.
- Media production metrics aggregate completed jobs, provider cost events, transcript durations, cost-per-priced-minute, and cost/duration evidence coverage for 7/30/90-day periods. The metric is bounded to the latest 5,000 completed jobs per company and period.

## Pricing and license evidence

Cost per minute uses only reported or estimated `cost_events` tied to a media job and transcript duration present in its media project's transcript document. Unpriced or missing evidence remains in the coverage counts. A null cost per minute means there is no matched cost and duration evidence; it does not mean zero cost.

Brand references may point to company-owned image/audio assets or a provider voice reference. An optional music license URL must be supplied by the company and is labeled as a reference only. Paperclip does not verify the license, ownership, or provider voice rights. Starter templates make no external asset or license claims.

## Queue priority and integration boundaries

Media Studio keeps its current per-company single-worker admission, budget checks, pauses, provider credentials, and execution path. Pending jobs now sort by bounded priority descending (0–100), then `createdAt` and `id` ascending. Existing jobs default to priority 0 and retain FIFO ordering. A priority edit is board-only, applies only while the job is queued, compares the caller's `updatedAt`, and writes an activity event. The claim checks that the selected priority is still current, so a concurrent reprioritization causes the worker to select again. Running jobs are never preempted. The existing FIFO index remains; `media_jobs_priority_queue_idx` supports the new worker ordering.

`GET /companies/:companyId/media-queue` returns the running job and a stable keyset-paginated pending page. `PATCH /companies/:companyId/media-jobs/:jobId/priority` accepts `{ priority, expectedUpdatedAt }`; a stale edit returns 409. There is no plan quota for video minutes implemented here, and this change does not claim one. Router registration and DB export/generated migration remain integration-root responsibilities.
