# S80 security settings implementation notes

## Implemented contract

- `createBetterAuthInstance` registers Better Auth 1.7.2's official `twoFactor` plugin with Paperclip as issuer. Email/password accounts may opt in from Security Settings. Enrollment requires the current password and a verified authenticator code; sign-in stays unchanged for existing accounts until enrollment is complete. The existing public `Auth` page switches to `LoginSecondFactor` only when the official `/sign-in/email` response has `twoFactorRedirect`; session invalidation/navigation occurs only after an official TOTP or recovery-code verification succeeds.
- TOTP enrollment/recovery/disable and session list/revoke call Better Auth's own endpoints with the current browser cookie. No application-generated OTPs, QR proxy, external QR service, or account-wide session actions are added. Recovery-code regeneration is an explicit user action because Better Auth replaces the old codes.
- Company retention is company-scoped and stored durably. The setting is expressly a requested preference with `enforcement: "not_configured"`; saving it does not trigger deletion. Company writes require `users:manage_permissions` through the existing authorization service. The existing company access UI/API remains the source of truth for roles and permission grants.
- Company portability remains on the existing export path. No account deletion or automated data deletion is introduced.
