# S95 agency workspace

## What this source implements

The agency workspace adds a narrow client-company provisioning flow on top of existing account admission and private package installation. An account owner/admin chooses a company already explicitly linked to that account, attests that a published private package version is appropriate to share, and requests a client company. A stable idempotency key and durable operation row bind retries to the same request, preselected company UUID, original requester, and pinned source package content hash. Every run and resume rechecks the requester's current source-company `agents:create` access and verifies that the current published source package still hashes to the pinned content. The canonical company factory creates that company archived. The existing product-account `grantCompany` service performs capacity admission; only after it succeeds does the flow add an explicit owner membership, copy the package into the client's private catalog, request/publish that version through the existing private workflow, and activate the company using `companyService.update`.

If account admission fails with a plan-capacity gate, the company stays archived and has no operator membership. The operation remains visible and can be resumed by the original requester after capacity is resolved. The operations endpoint is account-manager scoped and returns only the requester's bounded list. A stale `creating` lease can be reclaimed after expiry; the factory always uses the stable company ID and existing idempotent environment/bundled-agent setup. It does not auto-install or hire. Adding a client viewer is allowed only for a user with no existing membership or residual role grants; the operation refuses to mutate or downgrade existing access. Once the package is ready, the UI embeds the established installer, preserving its review, receipt, and approval behavior.

The portfolio reports monthly company and aggregate costs from `cost_events` and account usage from the existing account snapshot. Billing is account-level; no invoice amounts are fabricated or allocated to client companies. A bounded list exposes only the authenticated requester's in-progress operations so a page reload can resume/reconcile them. Client user access is a company-level `viewer` membership granted only through existing company permission management. Commercial account roles do not imply client-company ACL.

Public branding is explicit opt-in and exposes only display name, validated colors, and an optional company-owned PNG/JPEG/WebP/GIF asset up to 5 MiB. The public logo route streams the stored object with restrictive content headers. A requested domain is syntax-checked and stored, but its status is constrained to `unavailable`; there is no verification or hosting claim in this flow.

## Integration owned by root

- Export `productizationAgencyOperations` and `productizationAgencyBrands` from the database schema barrel.
- Export agency shared contracts from the shared barrel.
- Mount `productizationAgencyRoutes(db)` under authenticated `/api` routes.
- Mount `productizationAgencyPublicRoutes(db, storageService)` under `/api` before actor/auth middleware so its two public GET routes remain anonymous.
- Export the authenticated route factory in the route index if that index is used for generated route metadata.
- Add the authenticated agency page to the UI route tree. `PublicBusinessBrand` is a presentational projection component for a caller that has fetched the explicitly public brand.

The current source explicitly rejects client provisioning on a Cloud-managed instance because the canonical company-creation ownership path is Cloud-managed there. No alternate company factory or bypass is introduced.
