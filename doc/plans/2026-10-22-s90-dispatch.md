# S3 native runner dispatch correction

Date: 2026-10-22

`PaperclipRunnerToolAuthority.execute` advertised the Sprint 3 commercial tools through the runner catalog, but grouped most of their names with the Sprint 2 switch branch. The `SPRINT2_TOOL_NAMES` guard therefore rejected playbooks, proposals, decisions, delivery handoff, agreements, and upsell before their existing Sprint 3 dispatcher could run. Qualification, enrichment, and commitment extraction already had a separate Sprint 3 path.

The authority now detects the complete live `SPRINT3_TOOL_NAMES` set and forwards it to `dispatchSprint3Tool`. The dispatcher already maps those names to the existing playbook, proposal, commercial-decision, handoff, agreement, lead-qualification, and commitment wrappers. Sprint 2 CRM, lead, conversation, calendar, memory, and webchat tools remain on `callSprint2Tool` with its existing name guard.

Dispatch still occurs only after the bound run context, catalog descriptor, and work-mode checks. The API URL and run token come from the server binding; company, issue, agent, and conversation context are passed from that same bound run. No tool catalog entries, permissions, modes, phone operations, or review operations were added or widened.

Source inspection confirms that the Sprint 3 names remain in the existing `PRODUCT_TOOL_NAMES` set and are present in the semantic catalog used by `definitions()`. This change corrects routing only. No live run was accepted or executed, and no runtime/provider evidence is claimed.
