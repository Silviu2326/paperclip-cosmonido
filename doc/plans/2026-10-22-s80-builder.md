Esta limitación sustituye cualquier mención de un «banco real» utilizable en el texto de este primer corte.

## Contratos añadidos

- `packages/shared/src/productization/description-builder.ts` define la selección explícita del usuario (rol, IDs de skills/conexiones, autonomía solicitada y presupuesto mensual en USD), las versiones con procedencia `human_supplied`, y los esquemas de guardar, clonar y vista previa.
- `OnboardingJourney.builderDrafts` persiste la historia como parte del documento ya versionado con revisión CAS de `productization_onboarding`. Límite: 20 borradores, 10 versiones por borrador, 4.000 caracteres por descripción. No hace falta una tabla o migración nueva.
- La UI es `ui/src/pages/BusinessBuilder.tsx`, sin props públicas; obtiene la empresa desde `CompanyContext`. `businessBuilderApi` en `ui/src/features/productization/builder/api.ts` es su cliente.
- `productizationDescriptionBuilderService(db)` guarda versiones, clona una versión a un nuevo borrador, compara dos versiones y prepara una revisión de configuración que solo lee registros existentes. Sus escrituras CAS quedan auditadas como actividad.
- `productizationConnectionHealthService(db).list(companyId)` deriva disponible/conectada/autorizada/comprobada de `tool_connections`, grants activos de la empresa y salud almacenada reciente (24 h). Incluye sello observado y ruta de reconexión.
- `productizationBusinessExtractionService(db).availability(companyId)` informa si Firecrawl no existe, requiere reconexión/health check o está listo para una llamada de prueba. No realiza `fetch` ni ejecuta tools.
- `DailySummaryAssistant` en `ui/src/features/productization/builder/DailySummaryAssistant.tsx` interpreta con reglas visibles una solicitud acotada de resumen diario, muestra el payload/diff y sólo al confirmar llama `routinesApi.create` + `routinesApi.createTrigger`. Usa permisos de rutina existentes y puede guardar `require_external_activity`; no añade autonomía, presupuesto, conexiones, canales ni tool grants. Es un asistente determinista por formulario, no un copiloto conversacional ni una invocación LLM.

## Rutas para montar

Todas son board-only y usan autorización de empresa:

- `GET /companies/:companyId/productization/builder/connections`
- `GET /companies/:companyId/productization/builder/url-extraction`
- `POST /companies/:companyId/productization/builder/drafts` — `{ expectedRevision, draftId?, description, selection }`; crea borrador o agrega versión.
- `POST /companies/:companyId/productization/builder/drafts/:draftId/clone` — `{ expectedRevision, sourceVersion }`; clona a ID nuevo.
- `GET /companies/:companyId/productization/builder/compare?leftDraftId&leftVersion&rightDraftId&rightVersion`
- `POST /companies/:companyId/productization/builder/configuration-preview` — `{ expectedRevision, draftId, version }`; comprueba alcance/availability y no activa nada.

`productizationBuilderRoutes(db)` exporta el router. La raíz debe registrarlo en el montaje central; esta pista no edita `app.ts` ni `App.tsx`.

## Límites deliberados

Este servidor no tiene invocador de generación LLM para el constructor. La pantalla lo dice; el borrador persiste texto y opciones que la persona ingresó. El asistente de resumen diario tiene un parser determinista limitado a dos frases y hora 24h; enseña la propuesta antes del commit y no interpreta otros trabajos. Al confirmar, la rutina queda programada con las políticas y permisos actuales. No crea un canal ni una notificación WhatsApp. El banco de autonomía S3 real queda como acción aparte para un agente aprobado y utiliza el endpoint existente `/companies/:companyId/autonomy/bench`; el banco no eleva autonomía ni dispara la acción evaluada. `configuration-preview` no se llama sandbox ni afirma ser prueba de ejecución.

Firecrawl se invoca desde una acción separada del preview mediante el endpoint existente `POST /tool-connections/:connectionId/test-calls`. La UI toma el nombre/schema del scrape de solo lectura desde el catálogo actual y los candidatos desde `GET /test-agents`; el Tool Gateway revalida autoridad/política y puede exigir aprobación. El usuario elige expresamente cuándo llamar, la URL tiene que ser HTTP(S) sin credenciales y los hosts literales locales/privados se rechazan antes de la llamada. No hay `fetch` desde Paperclip. El resultado se muestra como texto plano sin verificar; solo se guarda en un borrador cuando la persona lo revisa y lo guarda.

No se necesita SQL ni migración. No se ejecutaron tests, builds, typecheck, scripts, servidores o migraciones por instrucción de esta tanda.
