# S95 builder copilot request ledger

Copilot proposal and dry-run requests now claim a durable row before the decision-model call. The unique company/feature/idempotency key binds one normalized semantic input hash and the authenticated actor. Reusing a key for changed input or another actor is rejected. The expected onboarding revision is deliberately excluded from the hash so an exact retry can replay after the original save advanced the revision.

The ledger stores only the decision request, exact provider response, result, invocation ID, provider/model identity, and timestamps. It stores no credentials. A successful provider response is written as `responded` before interpretation and journey persistence; retries can resume from that stored response without another provider call. Once the journey save completes, the row becomes `completed`. A terminal failure response is cached as `completed`. A reservation left `pending` after a process interruption, or explicitly marked `unknown` after an exception, fails closed and is never sent again automatically. This avoids duplicate provider spend; an operator can inspect the invocation ledger when an invocation ID was recorded. A hard process crash before the decision service returns can leave an unresolved reservation without a linked invocation, which is safer than charging again blindly.

Provider/model provenance is read by the exact returned `decisionInvocations.id`, company, and feature. It is never reconstructed from settings after the network call, so concurrent connection changes cannot misattribute the invocation.

Application execution continues to lock the onboarding row, create the routine and trigger through the same transaction-bound service, and write the success receipt in that transaction. The client has no result-receipt endpoint or service helper that can assert a successful creation. The autonomy bench route uses the native decision judge with the app-provided budget cancellation hook; candidate replay remains fail-closed until a verified safe runtime adapter is available.
