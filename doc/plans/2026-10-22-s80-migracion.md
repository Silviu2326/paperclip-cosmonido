## Notes and caveats

- **Retention is a stored preference only.** `productization_company_retention` records a per-company retention number of days. Nothing in this migration, and per the schema comment nothing reading that row, deletes data.
- **Notification tables** were read from `productization_notifications.ts` as it stood when this was written (the notification worker was finishing). `user_id` columns in the notification tables carry no FK to `user`, matching the schema. Re-compare once that worker reports done.
- **Portal SQL** was taken from `productization_customer_portal.ts` (the actual schema), cross-checked against the SQL in `s80-portal.md`. No differences other than naming normalization.
- **Long FK names**: several Drizzle-style FK names exceed PostgreSQL's 63-byte identifier limit and will be silently truncated (NOTICE). FK names are per-table and the truncated forms are distinct, so there is no collision. This matches what Drizzle itself would emit.
- Postgres `gen_random_uuid()` is used for UUID defaults, as in existing migrations.

## Inconsistencies found (not guessed; schema wins)

1. **Priority index reconciled by root.** Both schema and SQL now preserve `media_jobs_queue_idx` and add `media_jobs_priority_queue_idx` on company, status, priority DESC, created_at ASC, id ASC. No index drop remains in 0364. The ordering matches the new worker selector.
2. **Check constraints that exist in fragments but not in the schema were omitted**: `jsonb_typeof(...)` checks on `product_public_api_keys.scopes`, `business_webhook_subscriptions.events` and `business_webhook_outbox.data`; `quantity > 0` on `product_usage_events`. Add them to the schema first if wanted.
3. **Index differences vs. fragments**: `business_webhook_subscriptions_company_idx` is on `(company_id)` only in the schema (fragment had `company_id, status`). The migration follows the schema.
4. **`lead_forms.ts` still carries a header comment** saying it is "Not exported from schema/index.ts yet", while `index.ts` does export it. The comment is stale (not edited; out of scope).
5. **`user.two_factor_enabled` and `twoFactor`** were not in any numbered migration; confirmed absent from 0000-0363 by search before adding.
