# S90 consolidated schema migration

Date: 2026-10-22. This records the manual, additive migration assembled after 0364 from the S90 source fragments and the current schema declarations. No migration, generator, test, typecheck or build was run.

## Included in 0365

- Calendar delegated execution fields and the check tying public execution to a connection, exactly one host, and a delegation actor/time.
- Automation renewal and daily-brief goal references, plus the leased cyclic commercial automation cursor table.
- Durable account usage notifications with 80/100 threshold validation and deduplication by account, metric, period and threshold.
- Catalog installation receipt fields, resource identity indexes, expanded item status/kind checks, durable installation provenance on playbooks/forms, and the brand preset/request template draft tables.
- CRM phone call/callback records, their company-scoped voice-session foreign keys, consent/gate/status/receipt/phone checks, and queue/lookup indexes.
- External review links/events and CRM sync configs/links/jobs with their scoped references, idempotency indexes and state checks.
- `product_contact_imports`, matching `packages/db/src/schema/productization_imports.ts`: only CSV hash and bounded receipt, company/user FKs, and company/idempotency unique index. Raw CSV and inferred consent are not stored.

The migration is [0365_s90_consolidated_productization.sql](../../packages/db/src/migrations/0365_s90_consolidated_productization.sql); the journal entry follows 0364 at index 365. The original fragments remain unchanged as source evidence.

## Review notes and limits

- Foreign keys to tables introduced in earlier migrations are ordered after those dependencies. Cross-company voice session links use composite `(company_id, id)` foreign keys; optional phone callback dial session also uses the company-scoped key.
- The new playbook/form provenance columns are nullable for pre-existing rows and have partial unique indexes on `installation_item_id`, matching the source schema. The commercial cursor is keyed by lane and stores only its cursor/lease state.
- Existing S90 SQL fragments are additive to 0364 and are carried forward in one migration; no central migration or schema file was rewritten.
- The Drizzle journal has no 0365 snapshot. It was intentionally not synthesized: the request prohibited fictitious snapshots, and snapshot generation was out of scope. Snapshot drift/generation compatibility therefore remains unverified and must be resolved by the central migration owner before relying on schema-diff generation.
- Nothing here has been applied to a database. In particular, the `booking_types` columns use `IF NOT EXISTS`, but the named delegation constraint assumes the new 0365 migration is applied once through the journal as intended.
