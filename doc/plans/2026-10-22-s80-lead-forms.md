# S80 lead forms: management, publication and embed

Date: 2026-10-22
Status: source implemented in the S4 integration worktree. Not verified at runtime: no tests, builds, typecheck or migrations were run for this change. Verification was manual source review only.

## Scope

Authenticated, company-scoped management of the existing `lead_forms` table, plus the minimum change to the public submission route so the editor and the runtime use the same field list.

In scope:

- List, create, detail, update, archive/restore and publish/unpublish.
- Field configuration limited to the fields the public parser already understands.
- Stable slugs, source attribution label, consent copy.
- Active vs published distinction and a public address with a plain HTML embed snippet.
- Board-only mutations, company access checks, activity logging, optimistic concurrency.
- A board UI page with list, create dialog and editor.

Out of scope, by instruction: CRM provider calls, publishing live resources outside the public endpoint, route mounting, navigation entries, locale files, the Drizzle schema file, migrations and the migration journal.

## Field model

Stored in `lead_forms.fields` (jsonb) as the ordered list of enabled keys:

| Key | Public input | Stored in lead payload | Rule |
|---|---|---|---|
| `name` | text, 1–200 | `name` | Always enabled |
| `email` | email text, ≤320 | `email` (normalized) | Email or phone required |
| `phone` | text, ≤40 | `phone` (E.164) | Email or phone required |
| `company` | text, ≤200 | `company` | Optional |
| `message` | textarea, ≤2000 | `message` | Optional |
| `consent` | checkbox | `consent: { accepted, text, at }` | Requires `settings.consentText`; submission rejected without acceptance |

Disabled fields are stripped by the parser and stored as `null`. `language`, `clientId` and the honeypot `website` keep their existing behavior. Legacy rows with no contact field are read as email+phone so they keep accepting leads.

`settings` (jsonb): `{ sourceLabel: string|null, consentText: string|null }`. `sourceLabel` is written to every lead as `payload.formSource`.

Slugs: generated from the name on create (ASCII, lowercase, suffix `-2`, `-3`… on clash, up to 20 attempts). An explicit slug must match `^[a-z0-9]+(?:-[a-z0-9]+)*$`. The slug is immutable: the update schema is strict and rejects it.

## Active and published

- `active = true`: the form is in use. `archive` sets it false.
- `published = true`: the public address accepts submissions. A published form is always active. Archiving also clears `published`. Publishing an archived form returns 409; restore first.
- The public route accepts only `active AND published`. Anything else is 404.

## Endpoints

All responses are JSON. Errors use the existing `HttpError` shape: `400` validation, `401`, `403` (agent or viewer writes, cross-company board), `404` (missing or cross-company, identical bodies), `409` (stale `expectedUpdatedAt`, duplicate explicit slug, invalid lifecycle transition), `500`.

Form object (`LeadForm`):

```
{ id, companyId, slug, name, fields[], settings{sourceLabel, consentText},
  active, published, publicPath, publicUrl, createdAt, updatedAt }
```

Single-form responses (`LeadFormDetail`) add `embedHtml`.

| Method | Path | Access | Body / query | Response |
|---|---|---|---|---|
| GET | `/api/companies/:companyId/lead-forms` | company member, agents of that company | `status=active\|archived\|all` (default `active`), `q` (name contains, ≤200), `cursor`, `limit` (1–100, default 25) | `{ items: LeadForm[], nextCursor }` |
| POST | `/api/companies/:companyId/lead-forms` | board, company write | `{ name, slug?, fields?, settings? }` | `201` LeadFormDetail |
| GET | `/api/lead-forms/:id` | company member | — | LeadFormDetail |
| PATCH | `/api/lead-forms/:id` | board, company write | `{ expectedUpdatedAt, name?, fields?, settings? }` | LeadFormDetail |
| POST | `/api/lead-forms/:id/publish` | board, company write | `{ expectedUpdatedAt }` | LeadFormDetail |
| POST | `/api/lead-forms/:id/unpublish` | board, company write | `{ expectedUpdatedAt }` | LeadFormDetail |
| POST | `/api/lead-forms/:id/archive` | board, company write | `{ expectedUpdatedAt }` | LeadFormDetail |
| POST | `/api/lead-forms/:id/restore` | board, company write | `{ expectedUpdatedAt }` | LeadFormDetail |
| POST | `/api/p/:companySlug/form/:formSlug` | anonymous (existing) | JSON or urlencoded, ≤4 kB at the `/api/p` parser | `201 { ok: true }` |

Notes:

- `GET` list ordering is `updatedAt` desc, then `id` desc. The cursor is opaque base64url JSON of `{u, i}`; a malformed cursor is `400`.
- `companySlug` in public URLs is the company UUID, as the existing public surface already requires.
- Honeypot submissions still return `201` and store nothing.
- Lifecycle `expectedUpdatedAt` is required on all four actions.

## Concurrency

Writes use `UPDATE … WHERE id = ? AND company_id = ? AND date_trunc('milliseconds', updated_at) = <expectedUpdatedAt>`. Postgres stores microseconds and JavaScript keeps milliseconds, so both sides are compared at millisecond precision. Every successful write sets `updated_at = now (JS)`. If the update matches no row, the service answers `409` with `currentUpdatedAt`. Two concurrent saves with the same token cannot both succeed, because Postgres re-checks the predicate after the lock wait.

The UI keys the editor by `updatedAt`, so a saved or reloaded form replaces the draft with server state. It never refetches in the background on focus, so an unsaved draft is not overwritten silently.

## Activity log

Each mutation writes one row to `activity_log` with `entityType: "lead_form"`:

- `lead_form.created` (details: slug, fields)
- `lead_form.updated` (details: changed keys)
- `lead_form.published`, `lead_form.unpublished`, `lead_form.archived`, `lead_form.restored` (details: slug, active, published)

Reads are not logged, matching the existing lead routes.

## Limitations

- **No runtime verification.** Nothing here was compiled, linted, tested or run. The checks above are source review only.
- **Schema change pending.** `published` and `settings` do not exist in the Drizzle schema until the parent adds them. The service and route reference `row.published` and `row.settings`, so typecheck fails before step 1.
- **Embed is a plain HTML form.** It has no styling, no script, no success state and no redirect. The browser shows the endpoint's JSON `{ "ok": true }`. A cross-origin HTML form POST is a simple request, so it does not depend on CORS headers; I did not check the server's CORS configuration beyond that.
- **Consent is recorded on the lead, not on the contact.** The consent acceptance and text are stored in `lead.payload.consent`. The intake service still creates the contact with empty `consents`, because `leads/intake.ts` is outside this change. Contact-level consent needs a change to intake.
- **Concurrency token precision.** The check compares `updatedAt` at millisecond precision. Two writes inside the same millisecond with the same token cannot both be detected by the token alone, but the second update still matches no row once the first has written a new `updatedAt`, which is the intended outcome.
- **Public URL origin.** `publicUrl` and `embedHtml` use the request origin unless `publicBaseUrl` is passed. A proxy without `trust proxy` may produce `http` URLs.
- **Listing is bounded.** Lists return at most 100 rows per page and the UI loads 50 with no paging control. A company with more forms must search by name; the UI notes the truncation.
- **Slug is permanent.** A form cannot be renamed to a new slug. Duplicates need a new form and its embed must be replaced.
- **Field set is fixed.** Only the six keys above are supported, matching the public parser. Free-form questions or custom fields are not supported.
- **Archive is one-way in the UI for published forms.** Archiving withdraws the public address; restoring keeps it unpublished until published again.
- **Single-instance rate limiting.** The existing public limiter is in memory and is not shared across instances.
- **No agent access.** Agents can list and read forms through the company-scoped GET routes but cannot mutate them.
