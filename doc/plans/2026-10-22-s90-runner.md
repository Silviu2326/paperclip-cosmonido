# Catálogo y despacho de herramientas del corte S90

Fecha: 2026-10-22. Revisión de fuente; no se ejecutaron generadores, compilación, checks ni tests.

Se mantiene la distinción entre catálogo **live** y proyección de escenarios. El entrypoint que consume el servidor usa acciones con `live !== null`; `scenario: null` no vacía las herramientas de assignments, contexto, medios, CRM o ventas. La proyección de escenarios sigue sin incluirlas: registrarlas no les atribuye cobertura de evaluación.

Claude Code Haiku 5.5 incorporó los 58 identificadores live que faltaban en `spec/operation-groups/source.json`, repartidos entre grupos existentes y cinco grupos opcionales descriptivos. El integrador añadió las cinco herramientas de este corte: `review_link_create`, `review_status_get`, `crm_sync_status`, `call_summary_get` y `call_schedule`. Se sincronizaron el descriptor live, la lista de producto y el despachador S2, manteniendo los modos de lectura y mutación. Una devolución de llamada crea una solicitud; no existe una herramienta nueva para marcar números directamente. La revisión externa de un agente pide aprobación y nunca le entrega la URL.

La corrección de despacho S3 está en [su nota](2026-10-22-s90-dispatch.md). Los nombres S3 se despachan mediante su conjunto propio después de validar contexto y modo. Ya no caen en el guard de nombres del S2.

La autoridad sigue residiendo en el run real y las rutas de dominio, con empresa, permisos, consentimiento, presupuesto y aprobación vigentes. Los grupos de documentación no conceden permisos adicionales. Se actualizaron las expectativas del test de catálogo, pero no se ejecutó. La prueba de forecast también se escribió y no se ejecutó.

No se alteró el inventario normativo de aliases heredados para dar por cubiertas herramientas sin escenarios. Tampoco se editaron a mano los artefactos generados. Los emisores de contratos/operaciones y la preparación del vendor siguen pendientes bajo la restricción actual de ejecución; el contenido generado previo puede estar desfasado. No se afirma que `prepare:runner-vendor` ni el build pasen.
