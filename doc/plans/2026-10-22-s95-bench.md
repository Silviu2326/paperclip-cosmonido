# S95 WP4 native autonomy bench status

WP4 remains incomplete. The existing 20-case, non-heuristic promotion gate is
unchanged. `autonomy_bench_evaluator_unconfigured` still returns before run
insertion unless both a candidate and judge adapter are supplied. Candidate
inputs are projected explicitly without the reference answer, source ID, or
source provenance.

## Real judge adapter

`server/src/services/autonomy-bench-native.ts` provides
`autonomyBenchNativeJudgeDeps(db)`. It uses the company's configured Decision
Model through `decisionModelService` and a registered background feature. That
path rechecks the active shared connection and fresh credential,
reserves/settles company hard-stop budget, applies provider timeout and
cancellation, and writes the actual provider receipt to decision and cost
ledgers. It rejects unavailable, failed, unpriced, or malformed judgments and
loads provider plus exact model from the persisted successful invocation. It
does not create a second aggregate cost event.

`server/src/routes/autonomy.ts` wires the judge with the application's budget
cancellation hook. The candidate remains unset, so the route still rejects
before inserting a run. The judge therefore cannot make an otherwise
unsupported candidate replay qualify. No change was made to the promotion gate.

## Candidate replay remains unqualified

`packages/paperclip-runner/src/live/autonomy-replay.ts` is a reference-free
Codex transport primitive. It accepts candidate prompt inputs and never
receives a Paperclip database connection. Its `sandbox.preflight()` and
`transportFactory` are caller-supplied interfaces; no production host adapter
implements them. The preflight's `verified` flag is therefore a contract
assertion, not host evidence. `CapabilityLiveSessionService` defaults to
`createCapabilityRunnerdCodexTransport`. The replay disables Runner semantic
tools, but this does not confine native provider built-ins to the scratch
directory or deny network access. The Codex permission-profile name
`paperclip-runner-workspace-only` is not an OS sandbox attestation. Normal-run
remote sandbox targets are assembled elsewhere and are not wired as a
historical replay transport here.

The Runner semantic tools also use a fixed mock capability catalog, not the
target company's installed catalog or its exact authorization and dry-run
semantics. Empty semantic capabilities do not establish a catalog-bound
dry-run authority. The helper therefore returns `not_qualified`, and the
production route does not use it as a candidate.

To complete WP4 without weakening the gate, the server still needs: (1) the
target agent's effective adapter, model, instruction, skills, and runtime
snapshot with source provenance; (2) a catalog-bound dry-run tool authority
that cannot reach production services; and (3) a host-verified OS sandbox and
runtime transport. Normal heartbeat is not a replay boundary: it creates a
new run with live task and tool authority.
