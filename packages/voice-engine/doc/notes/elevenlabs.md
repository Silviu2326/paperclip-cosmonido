# ElevenLabs adapter notes

API reference checked on **2026-10-22**. Changes are limited to `src/providers/elevenlabs/`, `test/elevenlabs/`, and this file. Runtime imports outside the adapter use only `core/types.js` and `core/errors.js`. All network calls use injected fetch, with cancellation and timeouts covering response bodies.

## Endpoint decisions and remaining uncertainty

- **Models:** the nine requested models and defaults are preserved. The current [model overview](https://elevenlabs.io/docs/overview/models) also lists `eleven_v4`, `eleven_v4_turbo`, and `eleven_v3_conversational`; these are outside this task's pinned catalog. `eleven_v3` remains the requested flagship default. It supports HTTP output streaming, but is not a realtime input model; see [v3 audio tags](https://help.elevenlabs.io/hc/en-us/articles/35869142561297-How-do-audio-tags-work-with-Eleven-v3). Regional language tags are reduced to base languages for model selection. Legacy account availability and the requested 40,000-character Turbo limits were not proved against a live account. Pricing remains undefined with dated plan-dependent notes.
- **Multipart files:** use repeated `files` fields, matching the API schema/SDK, rather than literal `files[]` from some generated curl examples. Fetch supplies the multipart boundary. See [PVC samples](https://elevenlabs.io/docs/api-reference/voices/pvc/samples/create).
- **Voice Design:** the [current reference](https://elevenlabs.io/docs/api-reference/text-to-voice/design) places `output_format` in the URL query. The adapter reads it from `providerOptions` and sends it there. It accepts documented `audio_base_64` and alternative `audio_base64` response fields. `candidates` caps returned previews; it does not start extra paid generations. `stream_previews` is false because the shared result requires audio bytes. Provider text-length, guidance/loudness/seed constraints are left to the API.
- **Professional clones:** [ownership verification](https://elevenlabs.io/docs/eleven-api/guides/how-to/voices/professional-voice-cloning) is separate from consent. Create + samples + successful training returns `training` with `jobId = voice_id`. Verification-required responses return `pending_verification`. `providerOptions.verification_documents` accepts `AudioInput[]` (including document MIME types); `verification_text` supplies context for `/verification`. Manual submission returns pending because it is not approval. `verification_recording` can submit a CAPTCHA recording. Exported `getProfessionalVoiceCaptcha`, `verifyProfessionalVoice`, `requestProfessionalVoiceVerification`, and `trainProfessionalVoice` support completing later stages. Errors after creation include `details.voice_id` and disable automatic retry to avoid duplicate voices. Live ownership verification and training remain unverified.
- **Instant clones:** successful creation normally returns `ready`; explicit `requires_verification: true` returns pending. Both modes require `consent.attested === true` before network activity because cloning replicates the owner's identity. The attestation is preserved in `raw.consent` and the uploaded `consent_attested` label; it does not substitute for provider verification.
- **Voice editing:** the [documented endpoint](https://elevenlabs.io/docs/api-reference/voices/update) uses multipart POST and requires a name, so an omitted name is fetched first. Sample removal uses its separate DELETE endpoint. The final voice is refetched; these operations are not transactional.
- **Sound effects:** use `eleven_text_to_sound_v2` for loops, with duration 0.5–30 seconds per the [reference](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert).
- **Isolation and formats:** [isolation](https://elevenlabs.io/docs/api-reference/audio-isolation/convert) has no output-format selector. Headers/bytes identify WAV, MP3, FLAC or Ogg; unknown output is rejected. WAV metadata is read when available. Opus synthesis is treated as Ogg Opus (`audio/ogg; codecs=opus`); raw PCM is 16-bit little-endian (`audio/pcm`). Format entitlements remain plan dependent and were not tested live.
- **Dubbing:** the requested `/v1/dubbing` family is now documented as [legacy dubbing](https://elevenlabs.io/docs/api-reference/legacy/dubbing/create). File/URL jobs, status polling and downloads are implemented. Downloads preserve MIME type because video sources may return video; no audio-only format is invented.
- **Errors:** both legacy `detail.status` and current `detail.code` are supported, with HTTP fallback and numeric/date Retry-After. See [errors](https://elevenlabs.io/docs/eleven-api/resources/errors). Quota takes precedence over HTTP 401/429; `system_busy` maps to `provider_unavailable` as requested. Content-length validation is not a content-policy rejection.

## Contract gaps and local conventions

- `VoiceDescriptor` lacks training status/job fields. `getVoice` retains complete `fine_tuning.state` and adds `raw.status`: ready, training, pending_verification, or failed. The original model-by-model state remains authoritative. `CloneVoiceResult` carries its available status and job ID.
- Exported `listVoices` accepts `ElevenLabsVoiceQuery` for `pageSize`, `nextPageToken`, `voiceType`, `category`, and `signal`; the standard provider interface still uses `VoiceQuery`. Account pagination exhausts cursors unless limited. `searchVoiceLibrary` uses `VoiceLibraryQuery`, numbered pages and a default limit of 30. Library entries have origin community; original categories and public owner IDs remain in raw. Shared filters apply before the result limit.
- Models have no operation discriminator. STS descriptors identify themselves in notes; TTS rejects them. `supportsStreaming` describes native HTTP capability, not WebSockets or latency. Full SSML is not advertised; explicit SSML requests have markup stripped locally.
- Inline pronunciation rules cannot identify persistent dictionaries. Call `createPronunciationDictionary(ctx, name, rules, options?)`, then pass `providerOptions.pronunciation_dictionary_locators: [dictionary.locator]`. Rules without locators produce unsupported rather than silent loss or implicit repeated dictionary creation. XML is escaped; IPA/CMU are supported, X-SAMPA is rejected. Dictionary language defaults to en-US; override `options.language` as needed. Model phoneme support differs; aliases are more portable. See [pronunciation dictionaries](https://elevenlabs.io/docs/eleven-api/guides/how-to/text-to-speech/pronunciation-dictionaries).
- Native TTS body options pass through `providerOptions`, including dictionary locators and `apply_text_normalization`. Effective model, tagged text length, speed, format and v3 stability are validated. Unsupported models never receive `language_code`. Pitch/volume are ignored. Emotion shorthands whisper/laugh/happy map to whispers/laughs/happily; other short names become tags whose interpretation is model dependent.
- `SynthesisChunk` has no usage/request-ID field. Buffered synthesis includes the response request ID in result and usage. Streamed NDJSON alignment is treated as chunk-relative and accumulated by each frame's last aligned character end; unaligned trailing silence can cause drift. Exact timing would require audio-duration metadata or decoding absent from this contract. Split words are carried across frames; the final word may arrive in an empty-audio chunk. Word segmentation is whitespace-based, not linguistic segmentation for scripts without spaces.
- TTS usage uses the requested original `text.length`; tags, normalization, native text overrides and credit multipliers can differ from invoices. STS input duration is unavailable, so usage records input bytes and unknown cost instead of invented seconds. Extras do not fabricate shared operation kinds for dubbing/dictionary creation.
- No documented generic idempotency header is assumed; `idempotencyKey` is not transmitted. The adapter does not retry HTTP calls internally. Subscription health checks can require API-key permissions beyond synthesis access.
