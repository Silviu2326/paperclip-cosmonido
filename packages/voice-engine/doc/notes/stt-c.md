# STT C provider notes

Checked 2026-10-22 against official vendor documentation.

- **Mistral:** Research brief's older Voxtral model and endpoint uncertainty are superseded by official realtime docs. The current realtime model is `voxtral-mini-transcribe-realtime-3` and official WebSocket URI is `wss://api.mistral.ai/v1/audio/transcriptions/realtime?model=...`; Mistral documents bearer auth and event framing. This implementation currently exposes batch transcription only, and its batch model ID remains an assumption pending a verified official batch-model ID. https://docs.mistral.ai/studio/audio/speech_to_text/transcribe-in-realtime https://docs.mistral.ai/models/voxtral-mini-transcribe-realtime-3-0
- **Google:** Chirp 3 (`chirp_3`) supports synchronous REST recognize, word offsets, and diarization in recognize. Official docs describe streaming as gRPC `StreamingRecognize`, so the WebSocket-only injection contract cannot implement it; the provider advertises `streaming: false`. The REST recognizer route and inline base64 content are verified. API key auth header support and endpoint location host are based on the requested contract, not directly confirmed by the opened official REST reference. https://docs.cloud.google.com/speech-to-text/v2/docs/chirp-model https://docs.cloud.google.com/speech-to-text/docs/reference/rest/v2/projects.locations.recognizers/recognize
- **Azure:** Official docs identify `2025-10-15` as the latest generally available REST version (not the brief's placeholder `<current>`), confirm multipart `audio` and `definition`, region resource endpoint, subscription-key auth, locales, diarization, and channel options. This adapter is batch-only; the fast transcription REST method is synchronous. https://learn.microsoft.com/en-us/azure/cognitive-services/speech-service/rest-speech-to-text https://learn.microsoft.com/en-us/azure/ai-services/speech-service/fast-transcription-create https://learn.microsoft.com/en-us/rest/api/speechtotext/transcriptions/transcribe
- **Fish Audio:** Official search did not yield an accessible ASR wire-format reference. `/v1/asr`, JSON base64 audio, `language`, `ignore_timestamps`, model ID, and segment shape remain assumptions and require live docs confirmation before production use. No cross-import from TTS was made. https://docs.fish.audio/developer-guide/models-pricing/pricing-and-rate-limits
- **Rev:** Official async docs confirm bearer authorization, `/jobs`, status polling, transcript route, and `Accept: application/vnd.rev.transcript.v1.0+json`. The official streaming protocol endpoint and payload were not verified in the available docs search, so the adapter currently implements async jobs only. Multipart upload shape/options field and polling behavior remain assumptions; docs recommend webhooks over polling in production. https://docs.rev.ai/api/asynchronous/get-started https://docs.rev.ai/api/asynchronous/reference

Prices are omitted because current vendor prices were not verified. Google is REST recognize only and therefore batch input is inline-byte limited. Azure and Rev do not advertise streaming through these implementations.
